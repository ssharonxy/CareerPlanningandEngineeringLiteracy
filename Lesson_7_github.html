第3页·幕①为什么需要版本管理
约 10 分钟

你见过这些文件名吗？

作业_v1.docx
第一版，刚写了个开头
作业_v2.docx
改了第二段
作业_final.docx
以为完了
作业_最终版.docx
老师说要改
作业_最终版_真的最终.docx
又改了
作业_最终版_真的最终_老师要的.docx
到底哪个是对的？

没有版本控制时的三个灾难：

① 改坏了回不去——想改回昨天那版？找不到了。

② 多人改打架——3个人同时改一个文件，最后保存的把别人覆盖了。

③ 谁改了啥说不清——两周后这一段是谁写的？全凭记忆。

Git/GitHub 就是干这个的：给项目拍快照，改坏了能回退，多人协作不打架。

第4页·幕②Git和GitHub是什么
约 10 分钟

Git 和 GitHub 到底是个啥？

Git = 本地时光机

装在你自己电脑上的版本管理工具。
离线也能拍快照、随时回退。
没有网也能用。

GitHub = 云端仓库平台

把本地快照上传到网上。
队友才能看见、才能协作。
类似网盘，但专门存代码/文档版本。

一句话记住：Git 是装在你电脑里的"存档机器"；GitHub 是把存档上传上去的"共享书架"。

类比：Word 本地保存＝Git；把文档传到网盘共享＝GitHub。

课堂播放（约11分钟）：GitHub 新手指南（B站）——110万播放，快速了解 GitHub 上都有什么、怎么用它找资源。

课后系统学（70分钟动画精讲，不要求课堂看）：【精翻中文配音】图形动画讲解 Git 与 GitHub

第6页·幕④五个基本命令上手
约 18 分钟

五个基本命令，对应图上五站

0
status 看状态
先看现在在哪个区、改了哪些文件：git status　——动手前先看一眼，别盲操作。
1
add 暂存
告诉Git"这次把哪几个改动打包进快照"：git add 作业.docx　像交作业前先把文件拖进文件夹。
2
commit 存档
把暂存改动拍一张照，写一句message说清改了什么：git commit -m "feat: 提交作业1终稿"　前缀 feat＝新内容、chore＝杂项、fix＝修问题。
3
diff 看改了啥
commit前先看自己到底改了哪几行：git diff　红绿两色，加了啥删了啥一目了然。
4
push 推送 / pull 拉取
git push 把本地快照上传到GitHub；git pull 干活前先拉队友最新，避免白干。

commit message 要写人话：不能写"改了点东西"，要写"提交作业1终稿"——半年后你自己都能看懂改了啥。

第15页·材料①小组岗位能力对标报告
附录

材料①：对标报告怎么写、上台怎么讲

1
基本信息与成员名单
填写专业、班级、小组名称、组长/汇报人；逐人列姓名、学号与分工角色。
2
对标岗位概述
写明核心对标岗位、参考岗位（可选）与选择理由。
3
岗位能力要求拆解
从 JD 提炼硬技能、工程实践、职业素养三类核心要求，标注关键证据或来源。
4
成员能力对标
逐人三项1—5分并写出核心差距；可算小组平均分，标注共性差距与个性差距。
5
四年成长路径
大一打基础、大二强实践、大三深方向、大四冲就业，各阶段写里程碑与可验证产出。
6
结论与行动建议
总结3—5条核心结论，给出可执行的行动建议。

上台讲这四段

  • 目标岗位与对标结果
  • 四年成长路径
  • 本学期关键动作与里程碑
  • 自评指标与证据链

评分看什么

  • 报告数据可溯源
  • 对标分析到位
  • 四年路径可执行
  • 汇报逻辑清晰

组员岗位、能力不一致时：先取2—3个岗位的共同能力要求做交集分析；汇报讲小组共性发现，差异简要带过，不要只讲某一个人的情况。

第16页·材料③小组互评表
附录

材料③：互评表怎么打分、怎么写意见

评价维度（每项1—5分）看什么
岗位对标完整性岗位选择、JD 拆解、成员对标是否齐全
对标分析深度差距判断是否有依据，结论是否可执行
汇报表达4分钟内讲清逻辑，重点突出、条理清楚
团队协作分工明确，成员配合顺畅
整体印象报告规范，证据可追溯

评分刻度：5＝优秀　4＝良好　3＝中等　2＝及格　1＝不及格；五项满分25分，另填总体评分（1—5）与改进建议。

✓ 合格的互评意见

  • 写具体行为＋依据＋建议
  • "对标表把 JD 要求拆成硬技能、实践、素养三类，差距都有1—5分依据；建议补上大四冲刺岗位的投递时间点。"

✗ 空泛的互评意见

  • 只夸不具体、不给依据、不提建议
  • "讲得不错""PPT 很好看"——看不出好在哪，也没法改进。

互评计入期末 20%：客观公正、不打人情分；倾听时不打断、不使用攻击性语言。
