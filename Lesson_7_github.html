第5页·概念一
约 5 分钟

两个仓库：本地 vs 远程

① 两个命令：改动往哪传
push 推送：把本地快照上传到远程仓库
pull 拉取：把远程队友的最新改动下载到本地（pull＝先看新内容，再合并进来）
② 先对齐：本地和远程保持同一条记录
本地停在旧版本、远程已有新提交——干活前必须先 pull，避免在旧版本上白干
pull 之后本地和远程对齐到同一条记录，再开始改自己的部分

两个仓库各管什么：本地存储库（本地仓库）＝电脑本机上的版本库，add、commit 后的快照先存在这里，离线也能提交、随时回退；远程存储库（远程仓库）＝GitHub 上的共享版本库，push 上传后队友才看得见。

协作顺序（先对齐、后上传）：先 pull 拉到队友最新并对齐 → 改代码、add、commit 存进本地 → 再 push 上传远程；这样才不会在旧版本上白干、覆盖队友改动。

第6页·概念一
约 5 分钟

两种分支：主干 vs 个人分支

每个人开自己的分支改不同功能，最后一起合并回主干——互不打架
绿色 main 是稳定主干；蓝、紫两条 feature（特性分支）从主干开出平行副本，改完再合并回 main

为什么不能直接在main上改？3个人同时在main上改，你改一半我改一半，合到一起全是冲突。每人开自己的feature分支，改完再合并回main，就不会打架。

第7页·概念二
约 10 分钟

五个基本操作

1
add 暂存
告诉Git“这次要把哪几个改动打包进快照”——像交作业前先把要交的文件拖进文件夹
$ git add login.py把改动文件放进暂存区，还没真正存档
2
commit 提交快照
把暂存的改动拍一张照，写一句message说清改了什么，永久存在本地，随时能回退
$ git commit -m "feat: 新增登录页空值校验"-m 写清改了什么；前缀标类型：feat＝新功能、bugfix＝修缺陷、chore＝配置/杂项
3
push 推送
把本地快照上传到GitHub远程仓库，队友才能看到
$ git push把当前分支快照推到远程；省略远程名和分支名时，推到默认追踪的那个
4
pull 拉取
干活前先把远程上队友的最新改动拉到本地，避免在旧版本上白干
$ git pull拉取远程当前分支最新内容；pull＝先看新内容，再合并进本地
5
diff 查看变更
看你改了什么：哪几行加了、哪几行删了，红绿两色一目了然，commit前先看diff确认
$ git diff看还没 add 的改动；$ git diff --cached看已 add、还没 commit 的改动
