第3页·课程导入

四年后，你想成为什么样的工程师？

思考与讨论

  • 为什么选择这个专业？
  • 对未来职业的想象是什么？
  • 你心目中"好工程师"的标准是什么？
  • 从"找工作"到"用工程能力解决真实问题"，差在哪里？

破冰活动（2分钟）

  • 两人一组，互相交流上述问题
  • 每人用1分钟回答，1分钟倾听
  • 随机邀请2—3组分享
  • 关键词：专业认同、职业想象、责任意识

新时代工程师不仅要有技术能力，更要有家国情怀与社会责任感——从大国重器到民生科技，工程能力最终要服务于国家发展和人民福祉。

工程素养主线

解决"怎么去"

系统思维 · 需求转化 · 迭代开发 · 质量保障 · 协作沟通

用工程方法做职业规划

与通识就业指导课的区别：不是讲简历怎么写、面试怎么答，而是用工程师的思维方式——可验证、可追溯、可迭代——来管理自己的四年成长。

核心假设：职业规划不是大四的事，是大一第一天的事——时间的复利效应从现在开始计算

第5页·课程考核方式

考核方式：所有考核基于可核查产出物

平时成绩 50%

  • 考勤 5%——全勤优秀，缺勤超3次取消考试资格
  • 课堂参与 5%——模拟器操作、提问、讨论参与度
  • 小组协作 10%——Git提交规范、角色分工、看板管理
  • 平时作业 30%——作业1（自评表+岗位清单15%）+ 作业2（需求转化任务单15%）

期末考核 50%

  • 小组岗位能力对标报告 30%——岗位要求/现状/差距/改进计划
  • 个人IDP终稿 25%——含本学期复盘与下学期目标
  • 答辩表现 20%——每组4分钟汇报+1分钟问答
  • 复盘反思 25%——个人课程复盘（≥300字）

核心要求：所有考核项都要求可验证（有明确产出物和验收标准）、可追溯（有提交记录和版本历史）、可迭代（允许在反馈基础上改进提交）。

第6页·三个关键概念

三个关键概念：工程思维的基石

可验证 Verifiable

任何产出物必须有可测量、可复现、有阈值的验收标准

✗ "系统响应快"

✓ "95%请求响应≤200ms"

可追溯 Traceable

任何变更必须有记录，能回溯谁在何时因何做了什么

✗ "修改了一些内容"

✓ "fix: 修复登录超时，关联issue#42"

可迭代 Iterative

产出物不是一次完成，而是在反馈基础上持续改进

✗ IDP写定终身

✓ 每学期复盘更新

三者关系：可验证是基础 → 可追溯是保障 → 可迭代是目标。任何作业不可验证/不可追溯/不可迭代，就不是合格的工程产出。

第7页·8次课进阶路径

8次课进阶路径：认知 → 实践 → 综合

1
认知层
第1—3课：建立岗位意识，产出能力自评表 + 岗位清单 + IDP初稿
2
实践层
第4—7课：掌握工程方法，产出需求转化任务单 + 测试用例 + Git仓库
3
综合层
第8课：综合运用与交付，产出小组对标报告 + IDP终稿 + 课程复盘

每一层的产出都是下一层的输入——没有认知层就不知道练什么；没有实践层就无法完成对标和迭代交付。8次课是一条完整的能力成长路径。

第9页·能力评估四维度框架

能力评估四维度框架

硬技能

目前会什么？到什么程度？

工程实践

项目经验 · 竞赛 · 实习 · 开源

做过什么？产出过什么？

职业素养

沟通 · 团队协作 · 时间管理 · 文档写作

能力如何？有没有意识？

学习能力

自学速度 · 信息检索 · 复盘习惯

怎么学？会不会迭代？

自评要求：每个维度1—5分，必须写具体理由，不能只打一个分数。理由要可验证——例如"C语言能写链表操作"而不是"编程能力还行"。

第10页·课堂实践：自评与小组组建

课堂实践：个人能力自评 + 小组组建

自评表填写（5分钟）

  • 硬技能：1—5分 + 理由
  • 工程实践：1—5分 + 理由
  • 职业素养：1—5分 + 理由
  • 学习能力：1—5分 + 理由
  • 理由必须具体、可验证

工程小组组建（5分钟）

  • 3—4人一组，自由组合
  • 取组名，确定组长
  • 考虑能力互补性
  • 小组贯穿全课程
  • 下课前提交名单

诚实自评是工程思维的第一步——高估或低估都会导致规划偏差。自评表是后续IDP和岗位对标的基础数据。

第11页·工程素养五大支柱

工程素养五大支柱框架

系统思维

从整体角度看问题

理解组件关系与影响

不只见树木不见森林

需求转化

模糊需求 → 可验证指标

把"好用一点"变成

"完成时间≤30秒"

迭代开发

不追求一次做完美

先做最小可用版本

在反馈中持续改进

质量保障

测试用例 + 代码审查

自动化检查手段

不是"写完就完事"

协作沟通

清晰表达想法

编写可读文档

用版本管理工具协作

五大支柱与三个概念的对应：需求转化→可验证；迭代开发→可迭代；质量保障→可验证；协作沟通→可追溯。五大支柱是第4—7课的主线框架。

第12页·课堂检验

课堂检验：你能回答这三个问题吗？

Q1
什么是可验证？
用你自己的话解释并举一个正反例
Q2
你专业的五大岗位群？
说出至少3个本专业方向的岗位群名称
Q3
本次课产出了什么？
说出三样可验证的产出物名称

检验标准：Q1能说出"可测量、可复现、有阈值"；Q2能按本专业方向回答；Q3能说出自评表+岗位清单+小组名单。

第13页·总结：三个带走的概念

三个带走的概念

可验证

能不能用数字或是/否判断完成了没有？

可追溯

能不能回溯谁在何时因何做了什么？

可迭代

能不能在反馈基础上持续改进？

工程师的严谨与担当，从"把话说清楚、把事做扎实、把过程记下来"开始——这三个概念不仅适用于本课程，也适用于未来所有工程项目。
